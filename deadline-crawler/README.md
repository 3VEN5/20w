# 学校截止日期爬虫

定时抓取学校申请截止日期，和上一次对比，把变化记下来。日期库里的日期只是建议值，顾问确认后才生效。

## 现在能做什么

| 地区 | 学校 | 方式 |
|---|---|---|
| 美国 | Common App 总表里的 1126 所 | 自动解析 PDF，得到 ED / EDII / EA / EAII / REA / RD 的截止日和申请费 |
| 英国 | 牛津、剑桥、帝国理工、UCL、LSE、爱丁堡、KCL、曼彻斯特、布里斯托、华威 | 都走 UCAS，日期统一。日期写在 `manual_deadlines.csv`，程序每周监控 UCAS 页面 |
| 香港 | 港大、中大、科大、理工、城大、浸会、岭南、教大 | 日期从各校官网读出后写在 `manual_deadlines.csv`，程序每周监控各校页面 |
| 澳洲 | 悉尼、UNSW、ANU、昆士兰、西澳有日期；墨尔本、Monash、Adelaide 只监控页面 | 同上 |

英港澳的学校官网结构各不相同，没法用一个程序自动读出日期。所以做法是：**日期由人核实后写进 `manual_deadlines.csv`，程序每周检查官网页面上的日期有没有变，变了就提醒人去核对并改表。**

还没有日期的学校：
- 香港都会大学、香港恒生大学：没找到 2027 非本地生的日期页面。
- 墨尔本大学：官网日期页还停在 2025 年。
- Monash：官网写全年可申请，没有统一截止日。
- Adelaide University：截止日按专业列在各专业页面。

`manual_deadlines.csv` 里的日期是 2026-11-11 从官网读出的，个别页面版式较乱（备注里写了），请队友对照官网复核一遍。

## 怎么跑

```
pip install -r requirements.txt
python crawler.py
```

结果在 `data/` 里：

| 文件 | 内容 |
|---|---|
| `deadlines.csv` | 日期库，用 Excel 能直接打开 |
| `deadlines.json` | 同一份数据，给程序用 |
| `deadlines_web.js` | 精简版，网页原型用它带出截止日 |
| `changes.md` | 每次运行和上一次相比的变化，最新的在最上面 |
| `state.json` | 上次抓取的状态，不用管 |

每条日期都带：来源、来源网址、来源自己标注的更新日期、抓取时间。

## 定时运行

两种办法，任选一种：

1. **GitHub Actions（推荐）**：仓库根目录的 `.github/workflows/crawl.yml` 会在每周一北京时间早上 8 点自动跑，有变化就提交。有需要人工核实的变化时，这次运行会显示失败，GitHub 会发邮件。
2. **自己的电脑或服务器**：Mac / Linux 用 `crontab -e` 加一行
   `0 8 * * 1 cd /路径/deadline-crawler && python3 crawler.py`

每周一次就够了。Common App 总表一个申请季只改几次，抓得太勤没有意义，也不礼貌。

## 加学校、改日期

- 加一个要监控的官网页面：打开 `sources.yaml`，照着已有的写法加一行。
- 加一条日期或改日期：打开 `manual_deadlines.csv`（Excel 能开），加一行或改一格，记得把"核实日期"改成当天。

## 已知的限制

- Common App 总表里没有的美国学校查不到（比如耶鲁、加州大学系统）。
- 有些学校网站会拒绝自动访问。遇到这种情况变化记录里会写"这次没抓到"，那所学校就只能靠人定期看。
- 总表里个别学校有多行，第 2 行起会在校名后标"请核对"。
- 解析靠的是 PDF 里每个字的位置。Common App 如果改了版式，程序会发现解析出的条数太少，保留旧数据并提醒，不会写入错的日期。
- 截止时间是学校当地时间，换成北京时间可能是第二天，这一步还没做。
- 专业级的截止日期（部分港校、加拿大学校）不在范围内。

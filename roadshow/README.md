# 20w · 顾问工作台对比版

以原服务器版 `app/` 为基础，原目录未改。左右对照：`app/static/index.html` 与 `roadshow/static/index.html`；`app/server.py` 与 `roadshow/server.py`。新增交接摘要与交互在 `static/workbench.js`。沿用原来的数据库基础结构、AI、话术、学校日期库及 PDF 资源，无需复制整个仓库的依赖。这不是 Claude Artifact 的替换版。

## 运行单人路演

从仓库根目录执行（Python 3.10+）：

```sh
python3 -m venv .venv
.venv/bin/pip install -r app/requirements.txt
.venv/bin/python roadshow/run.py --demo --port 8766
```

打开 http://127.0.0.1:8766 。仅监听本机；为一名演示者服务。每次启动新建独立临时数据库，即使设置了 APP_DB 也不会读取该路径。一键重置仅清除本次虚构案例及会话；不是机构数据清理工具。

1. 进入王老师工作台，打开学校邮件，解析离线样例。对照原句，确认写入。固定样例不调用线上 AI。
2. 回到今日跟进：复制不会留痕；实际发出后单独确认。
3. 核对学生承诺“我今晚把英文成绩单发给您”。承诺日 11/16、顾问复查 11/17、学校截止 11/20，互不覆盖。
4. 确认移交给陈老师，进入次日。此时登录身份和数据库内的学生负责人都变更了，不只是切换页面标签。
5. 陈老师首页自动展示按当前数据生成的接手摘要。点“已跟进，安排复查”，摘要即时反映下次日期；事项仍未完成。随时可以一键重置，从头再演。

## 与原版的差异

| 原版 | 对比版 |
| --- | --- |
| 顾问首页为总览；计数未覆盖单独逾期 | 默认今日跟进，计数按事项去重，逾期、到点复查、机构临期优先 |
| 老板身份筛选可能因 ID 类型不同而显示为空 | 统一比较 ID，保留选中态 |
| 复制话术同时记为已发 | 剪贴板和业务写入分离，约定仅标记本次消息包含的事项 |
| 单条事项缺少独立的承诺与复查日期 | 学生页可对未结事项记录承诺、安排复查；AI 建议的完成和改期等高影响操作默认不勾选 |
| 靠人重写学生交接情况 | 真实变更负责顾问。接手时使用当前事项与留痕生成摘要；首页重新聚焦、操作后或空闲轮询时更新 |

非演示模式：去掉 `--demo`；默认使用新文件 `roadshow/data/app.db`。需要账号时，用同一个绝对 APP_DB 路径运行原版 `app/manage.py new-agency`。此模式没有重置、演示切号、模拟日期或离线提取接口。试点前用脱敏数据验证本机构规则；不要直接指向原版在用的数据库。

## 复跑浏览器验收

安装 `playwright` 和 Chromium 后执行 `python roadshow/check_browser.py --shots /tmp/20w-shots`。可以用 `--chrome /path/to/chrome` 指定本机 Chrome。脚本另起临时服务，不会重置正在演示的实例。
